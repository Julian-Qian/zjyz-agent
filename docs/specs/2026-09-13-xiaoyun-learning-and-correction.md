# Spec：小云 Agent 持续学习与自净化

状态：用户已确认第一期，代码已落地；真实模型验收与上线尚未执行。

## 1. 目标与范围

让用户通过自然对话教育小云：理解纠正、修正当前回答、保存有依据且有范围的知识、跨会话应用、替换和撤销错误记忆，并验证是否重犯。

本次建议批准实施第一期完整纠错闭环。第二期执行经验自改进仅作架构预留，另行确认。保留现有 Spring Boot、MySQL、知识检索与 V2 执行框架，不引入 Hermes Python 运行时。

不自动修改模型权重、生产代码、计算公式或权限；不自动导入全部历史聊天为有效知识；不改动租出、归还、赔偿等单据的计算或操作流程。部署与迁移执行另按发布流程处理。

## 3. 用户体验

### 教导与即时修正

用户说“你理解错了，……”“记住以后……”，或在上一条回答后直接给出替代解释，无需特殊指令。识别器同时输出对话行为、关联消息、纠正内容、适用范围及是否继续原任务。

例：上一轮问在租数量，用户随后说“租出增加、归还减少、赔偿不影响在租数量”。立即承认是在纠正规则理解；其中赔偿口径在核验前只作为待核验内容。不能回复问候、要求重新说明查询对象，或因没调用经营查询工具而判定受阻。

学习卡显示“本次理解 / 已记住 / 待核验 / 存在冲突 / 已撤销”及一句原因。没有持久化成功不得显示“已记住”。待核验记录已保存时，教导任务可以完成，卡片的核验状态独立于任务状态。

### 查看、继续与撤销

在 AgentBeta 增加“学习记录”抽屉，支持按关键词、类型、范围和状态筛选；详情显示内容、来源、依据、版本和替代关系。可纠正、撤销；已回答的教导不重复弹出确认卡。

“忘掉刚才那条规则”若唯一可定位则直接撤销；存在多条合理候选才询问具体一条。撤销停止使用，审计历史保留；界面明确区别于删除全部原始数据。

范围缺省为本人在当前企业内，项目来源事实继续受项目权限约束。发布到企业/项目共享范围需有现有知识管理权限并有明确共享意图；无需每次为个人偏好弹审批。

## 4. 学习内容与生效规则

| 类型 | 核验方式 | 自动生效条件 |
| --- | --- | --- |
| 表达偏好 | 用户本人直接表达 | 保存成功后在本人范围生效 |
| 别名与指代 | 检查实体、歧义及访问权限 | 唯一匹配后生效；不永久记忆动态负责人关系 |
| 业务规则 | 匹配受信业务知识的版本、适用条件和证据 | 与已发布规则一致且范围合法；无依据则待核验 |
| 能力纠正 | 当前能力注册、可用性及必要的只读执行证据 | 验证后记录适用版本；用户一句“支持”不创建能力 |
| 系统缺陷 | 期望行为和实际行为差异 | 形成问题记录及回归案例，不作为计算真值 |

已发布业务说明代表规范，工具结果代表对应范围和时间下的实际结果；冲突不能简单以代码或用户任一方永远优先解决。系统无法核验的规则保留原因与下一步，不要求用户确认“系统是否支持”。

后台无需开放代码读取或任意 SQL 来核验规则。通过已有知识来源、能力清单和固定只读工具完成；缺少证据就保持待核验。

## 5. 第一期架构与执行流程

1. 输入授权与会话恢复后，先取当前纠错引用、有效学习摘要，再执行意图识别；普通业务查询路径仍可使用。
2. dialogueAct 增加 TEACHING、FEEDBACK、MEMORY_REVOKE；保留 relationType 语义。输出 learningActions 与 resumeOriginalTask，避免“纠正并继续查询”只能二选一。
3. 新增学习协调服务，提取候选项、去重、校验范围、查冲突、调用验证器。模型负责语义提取，后端决定权限和生命周期。
4. 内容写入现有知识来源/版本体系，学习元数据、验证记录与引用分开记录；完成数据库事务后返回真实学习状态。
5. ContextBuilder 和执行器按用户、企业、当前项目权限加载有效条目。模型按需展开正文，不全量拼接。
6. 当前轮通过学习结果消息立即应用修正；后续轮重新检查有效版本，不必等新会话。历史原文不改写，摘要中的旧结论追加失效说明。
7. 回答前重新检查引用是否有效和是否覆盖原问题；最多一次有界修正，禁止无限自检。需要实时数字的回答仍调用业务工具，不使用历史金额或库存记忆替代。

建议组件：AgentLearningService、AgentLearningVerifier、AgentLearningRetriever、AgentLearningController；按现有 controller/service/mapper 分层实现。扩展 Interpreter、ContextBuilder、Coordinator、Executor 和回答展示适配，不建立第二套经营任务执行器。

### 自净化及检索一致性

- 状态：PENDING_VERIFICATION、ACTIVE、CONFLICT、SUPERSEDED、REVOKED、REJECTED。
- 新规则替代旧规则必须原子提交；核验未通过的新版本不能提前覆盖旧版。发现可信冲突时可将涉及旧规则隔离为 CONFLICT。
- SQL 状态是生效依据。向量索引仅提供候选，返回前再按 SQL 版本、状态和权限过滤；撤销立即阻断新检索及尚未输出的旧引用。
- 缓存键包含权限与学习版本；撤销/替代增加版本并失效缓存。每个回答保存实际引用版本，可定位受影响会话。
- 相同输入幂等，完全重复合并；近似重复与冲突由语义判断提出候选，再通过条件和版本校验，不能仅靠相似度覆盖。
- 外部文档和工具内容仅为有来源的数据，不能直接成为用户教导或覆盖系统指令。禁止保存凭据、原始日志大段文本或跨权限数据为常驻记忆。

## 6. 数据模型与事务

拟新增（最终命名遵循仓库现有表约定）：

| 表 | 主要字段和用途 |
| --- | --- |
| agent_learning_entry | id、cid、ownerUserId、scopeType、projectId、kind、status、sourceId、activeVersion、supersedesId、originThreadId/messageId、dedupeKey、rowVersion、created/updatedBy/At |
| agent_learning_event | entryId、entryVersion、action、actor、clientRequestId、evidenceRefs、reasonCode、before/afterStatus、createdAt；记录核验、替代、撤销与重试 |
| agent_learning_usage | runId、messageId、entryId、entryVersion、usageType、createdAt；区分检索候选与实际引用 |

正文及正文历史复用知识库，不重复建设全文/向量存储。扩展知识 sourceType 与检索过滤，使未核验学习项不泄漏到普通知识检索；个人学习源不能通过旧企业知识列表暴露给其他用户。

按 cid、ownerUserId、status、projectId 建必要组合索引；幂等请求建立唯一键，rowVersion 用于并发控制。实现前核对现有迁移编号，脚本以 use zjyz; 开头，兼容 MySQL 8.0 以下。默认空表，不将历史对话自动回填为 ACTIVE。

来源版本、学习状态、事件在同一事务更新；外部检索索引任务在提交后通过可重试任务执行。失败不影响已存在的经营查询功能，不返回虚假的保存成功。

## 7. API 与权限

沿用 /agent 前缀、现有响应包装和 AGENT_ENABLED 会员控制；前端新增 src/api/agentLearning.js。拟定接口：

| 方法/路径 | 请求 | 返回 |
| --- | --- | --- |
| GET /agent/learning/capabilities | 无 | canReadOwn、canManageShared 等后端计算权限 |
| GET /agent/learning/entries | pageNum、pageSize（最多50）、keyword、kind、status、scopeType、projectId | items、total |
| GET /agent/learning/entries/{id} | id | 内容、范围、版本、状态、授权可见的来源/事件 |
| POST /agent/learning/entries/{id}/correct | content、expectedVersion、clientRequestId | 新候选版本及核验状态 |
| POST /agent/learning/entries/{id}/revoke | expectedVersion、clientRequestId、reason可选 | 最新状态及版本 |
| POST /agent/learning/entries/{id}/verify | expectedVersion、clientRequestId | 核验结果或排队状态，不强制置为ACTIVE |
| POST /agent/learning/entries/{id}/publish | expectedVersion、scopeType、projectId可选、clientRequestId | 已核验条目的共享版本；未核验不能绕过验证 |

自然对话创建学习项复用 POST /agent/v2/threads/{threadId}/turns，不另设强制输入通道。Task 结果和流事件增加 learningResults（entryId、version、status、summary、scopeLabel、reason、actions），字段向后兼容。

身份和 cid 从服务端认证获取；不能信任请求中的用户、企业、项目授权。共享管理沿用现有知识管理授权，个人编辑仅限本人；共享发布不覆盖个人原条目。详情和引用仍检查来源项目权限。

无权限/不存在、版本冲突、重复请求、待核验、保存失败使用现有错误包装及对应业务错误码；并发冲突提示刷新，不静默覆盖。无结果返回空列表。

继续使用现有 /agent 代理路径；发布前验证新增子路径实际通过 nginx、鉴权和会员拦截，不假定已有前缀即无需检查。

## 8. 前端状态

- 对话中显示精简学习卡：规则、状态、范围；依据和历史折叠展开，技术枚举/日志不进入自然语言正文。
- 保存中、待核验、冲突、失败可区分；失败时允许幂等重试。待核验不是强制用户回答的澄清。
- 学习记录抽屉提供加载、空列表、错误重试及只读权限状态；危险程度低且可撤销的本人纠正不重复弹确认。
- 只有确实存在多个被纠正对象或实体歧义才提一个具体问题；其余独立工作继续。

## 9. 验收与评估

必须覆盖真实对话及同义改写，不能只测试关键词：
1. 规则问答后用户补充解释，被识别为教导；不会返回问候或因无经营工具结果标记受阻。
2. 个人表达偏好保存后，新会话仍应用；服务重启后保留。
3. 无证据的业务规则显示待核验，不宣称核验或记忆生效。
4. 有依据规则生效后同义问题正确应用；实时数值仍查询。
5. 能力纠正查真实能力；不存在的工具不会因用户说支持而获得执行资格。
6. “你查错人了，是另一位小何”能纠正并继续原任务；歧义时只澄清人员。
7. 替代/撤销后新查询及未输出答案不引用旧规则；并发、索引延迟和缓存命中仍满足。
8. 跨企业、跨用户、撤销项目权限及旧知识API均不泄漏个人/项目学习内容。
9. 同一请求重试不重复创建；版本冲突不覆盖他人修改；保存失败无假成功。
10. 恶意附件指令、错误教学及相似但不同业务口径不会自动污染有效规则。

第一期建立至少40条固定案例，包含截图问题、同义改写、多轮和反例；留出未用于调提示词的改写集。记录改动前后结果、真实模型/配置。核心纠正识别与应用目标≥90%，隔离/撤销/幂等确定性测试全部通过。模型自评不能作为唯一通过依据，关键口径使用人工标注或确定性断言。

执行后端定向 Maven 测试、前端定向测试和构建、真实模型对话回放及浏览器交互验证。缺少模型或服务环境则标记未验收，不能只凭模拟测试宣称学习能力完成。

## 10. 分期与发布

第一期（本次确认范围）：数据与状态 → 纠正识别及核验 → 检索/失效接入 → API及前端学习记录 → 真实场景回归。包含缺陷反馈记录，暂不自动修改技能。

第二期（另行确认）：任务完成/失败后异步复盘；生成带前置条件、工具步骤、失败恢复和验证方式的经验技能；先作为候选，经回放验证才发布。只引用注册工具，不允许任意脚本；工具版本变化后重新核验。加入重复合并、过时检查及效果下降回滚。

通过功能开关控制学习写入、检索和共享发布，可分别关闭。试点企业先启用；关闭后旧经营查询继续工作，学习数据保留审计。代码确认不等于自动部署许可，本方案不执行迁移或发布。

第一期已获确认；第二期保留设计，待第一期验收后单独启动。
