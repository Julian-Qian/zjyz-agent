# 小云材料赚钱问题：指标防错与后续收入分析

用户已确认开始落实此前两阶段建议。本轮落实第一阶段：意图指标、工具边界、澄清和回归测试；第二阶段材料收入分析先完成数据来源核查。

## 问题与目标

“今年帮我赚到最多钱的材料是什么”被执行为租出数量排行。数量、单据次数、租金收入、回款和利润不能互相替代，“最多”只表达排序。

本轮验收：

- 模糊赚钱口语进入金额口径澄清，同时说明当前没有材料收入、回款、利润的可靠汇总能力。
- 明确金额指标时说明能力缺口，不查询或展示数量榜冒充答案。
- 模型错误改写原话时，服务端仍能识别本次问题并阻止错误执行。
- 工具被直接错误调用时，在数据库读取前拒绝金额问题。
- 保留普通材料数量/次数查询、明确改成数量的纠正、项目回款和合同单价分析。
- 保存正确目标、分析对象、指标和时间，供澄清后的任务继续使用。

## 实现范围

后端增加独立分析对象 `analysisTarget` 和指标数组 `requestedMetrics`，作为 TaskSpec JSON 的可选字段，兼容历史任务。理解器负责语义提取；服务端对原始本轮用户消息与结构化指标做防错校验，不扫描旧聊天命中词来决定当前任务。

V2 执行器复用现有 `WAITING_USER` 澄清与 `BLOCKED` 能力不足流程。材料流水工具增加执行边界校验；工具目录与能力清单说明数量/次数边界。旧版不支持指标策略补充赚钱口语。

没有新增 HTTP 路径、数据库字段或迁移；没有修改项目单据、金额计算或权限。前端继续使用已有澄清事件、任务状态和消息展示，无需修改组件。后端变更需部署后才在线上生效，本轮不包含生产部署。

## 第二阶段数据来源核查

在后端源码中确认以下候选来源：

- `SettlementRentFeeSegmentEntity`：材料标识/名称/规格、计费区间、材料租费、基础金额、递增金额和停租扣减等。
- `SettlementDocumentEntity`：业务方向、结算期间、正式单状态、最终金额、计算版本及快照。
- `SettlementDocumentServiceImpl.persistRentFeeSegments`：保存结算材料分段；正式结算写入 `ACTIVE`，作废使用 `VOID`。
- 当前企业财务技能以项目为粒度汇总正式结算本金和登记付款，不能直接解释为材料收入、材料回款或利润。

以上仅证明存在候选表结构和写入路径，未查询生产数据，尚不能证明历史明细完整。收入榜上线前须确定并验证：

1. 期间按结算归属还是实际计费日期切分，尤其跨年区间及最低租期补差。
2. 正式结算、作废、修订、重复分段与历史版本的唯一有效口径。
3. 材料租费与结算总额之间的杂费、赔偿、停租、优惠及调整差异。
4. 历史单据缺少分段时报告覆盖率，不能把缺失当零收入。
5. 同名不同材料、材料改名、跨规格汇总与币种规则。
6. 回款是否存在材料级分摊依据；利润是否具备采购、租入、损耗、折旧等可归集成本。

应先实现独立、可核对的“已结算材料租金”能力，再考虑回款和利润。金额结果应按同一币种排序，先给出领先材料、金额和占比，再附项目贡献与统计口径；不按材料数量单位拆金额榜。

## 验证方式

使用 Maven 定向测试覆盖理解器结构化字段、原话防错、V2 完整执行入口、数据库读取前拒绝、澄清上下文、旧版意图、工具权限与原有数量排行。执行入口测试模拟理解器错误返回数量指标，检查最终任务状态、消息无排行卡片且未调用业务规划器/工具。

测试中的模型响应使用固定桩，不代表线上模型的自然语言准确率；后续部署后仍需用真实模型验证本例及澄清续问。
