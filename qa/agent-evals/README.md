# 小云三类能力候选评测集

`three-capability-holdout.jsonl` 包含 **120 条候选场景**，用于后续构建验收用例。本文件名保留 holdout，但本集由开发过程生成且开发者可见，**不是真正独立盲测集**，不得用它单独证明泛化能力。另需由未参与实现的人员在独立位置维护未公开问法、组合和数据分布；发布前再运行该保留集。

本次只创建、校验数据文件，没有调用模型或业务接口，**没有通过率、耗时、成本或线上成功结论**。具体项目、金额、权限、合同与功能开关均需绑定测试fixture；当前 `dataFixtureStatus=UNBOUND` 不能作为可以执行的完整实测环境。

## 场景分布

| 主标签 | 条数 | 关注点 |
| --- | ---: | --- |
| guidance | 20 | 版本、入口、规则、业务方向、权限前提、未知功能 |
| query | 25 | 对账排期、材料余额、历史时点、审核、分页、单位、实体消歧 |
| analysis | 20 | 收入/回款/利润、利用率、风险证据、可比口径、缺失指标 |
| contract | 20 | 付款、赔偿、角色视角、表格、OCR、附件缺失、原文定位 |
| mixed | 10 | 多要求覆盖、指导与数据、文件与经营分析、读写边界 |
| followup | 10 | 条件继承、指标纠正、实体澄清、附件继承、删除与重验 |
| security | 10 | 跨租户、权限撤销、附件ACL、提示注入、系统秘密 |
| failure | 5 | 理解失败、超时、额度不足、重启恢复、分页失败 |
| 合计 | 120 | 同一句可能出现在不同故障上下文，属于不同场景 |

## 每条字段

- `id`：稳定场景编号。
- `prompt`：测试用户原话，不要求特定回复措辞。
- `context`：隔离测试要求、待绑定条件，以及部分场景的前序对话/故障注入。context 是测试控制材料，不应全部拼成用户提示；要通过真实对话、权限设置、合成文件或受控故障建立前态。
- `expectedBehavior`：语义与业务行为要求。可支持的能力应真实完成；不支持部分必须说明影响。
- `forbiddenBehavior`：不能出现的编造、错误完成或权限扩张。
- `requiredEvidence`：结果核验所需来源及覆盖；拒绝场景不能为了生成证据而先读取禁止访问的数据。
- `tags`：场景类别与未实测状态。

正确性不以固定工具名称、固定输出句式、固定项目ID或特定模型为标准。允许替代实现，但最终范围、口径、引用和权限必须满足场景要求。只返回“做不了”不能通过一个已提供充分数据且当前能力支持的正向场景。

## 运行前准备

1. 为每个案例独立绑定fixture版本：冻结执行日期/时区、认证租户/用户/角色、项目候选、业务记录、审核与撤销状态、材料单位、账期/付款条款、功能开关、模型版本。用合成或经授权脱敏数据，不默认使用生产。
2. 正向场景应有足够数据，可计算期望值及原文位置；缺数据/不支持指标场景需明确缺什么，而不是笼统把全部案例设成不可用。
3. 文件场景准备对应PDF/DOCX、扫描质量、主合同/附件关系、解析覆盖基准与删除时点。不能拿同一份简单合同代替所有文件条件。
4. 追问场景先建立 `previousUser/previousTask/pendingClarification` 描述的前态。必要时分别验证正常多轮和页面刷新后的恢复。
5. 权限场景设置至少两租户和可访问/不可访问对象；故障场景通过测试桩或受控环境注入，不能改变生产权限或破坏生产服务。
6. 显式记录当次可用能力与数据完整性。实现当前没有某项能力时，评估是否正确说明边界，并另外报告“能力未具备”；不能把安全拒绝统计成已经完成该产品能力。

## 判定与记录

建议要求级人工判定：范围/实体/时间是否正确；指标与单位是否正确；结论是否被所引证据支持；是否覆盖全部子要求；缺数据、失败与空结果是否区分；是否保持权限与读写边界；追问是否保留或正确替换条件。

结果记录至少含 caseId、fixtureVersion、release/model/prompt版本、attempt、要求级结果、实际引用、故障原因、是否发生禁止行为、耗时/成本（真实取得才填写）。建议分类使用 `PASS/FAIL/BLOCKED_FIXTURE/UNSUPPORTED_CAPABILITY/NOT_RUN`，不要把未绑定fixture或未运行标成通过。产品能力完成率与安全降级正确率分开报告。

同一模型场景可重复3次观察波动，但独立运行才计样本；缓存复用不算新的稳定性测试。按类别报告分子/分母，避免高频简单指导掩盖合同或权限失败。任意跨租户泄漏、虚构关键金额或虚假条款引用属于发布阻断问题。

## 本地数据校验

```sh
python3 qa/agent-evals/build_holdout.py
python3 - <<'PY'
import json
from pathlib import Path
p = Path('qa/agent-evals/three-capability-holdout.jsonl')
rows = [json.loads(line) for line in p.read_text().splitlines()]
assert len(rows) == 120
assert len({row['id'] for row in rows}) == 120
required = {'id', 'prompt', 'context', 'expectedBehavior', 'forbiddenBehavior', 'requiredEvidence', 'tags'}
assert all(required <= row.keys() for row in rows)
assert all(row['prompt'].strip() and row['expectedBehavior'] and row['requiredEvidence'] for row in rows)
print('120条候选场景结构校验通过；未执行模型评测。')
PY
```

生成脚本中的条目是人工编写的不同任务与边界场景，不是循环换名的同义问法扩充。修改场景时先更新生成脚本，再重建JSONL并评审差异；不要通过改期望结果迎合当前模型输出。只需消费数据时直接读取JSONL，不必运行生成脚本。
